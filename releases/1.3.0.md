# GLAZE UI V1.3.0 — Adaptive Resonance

**Lifecycle:** Stable  
**Promotion decision:** 2026-09-07  
**Integrated implementation anchor:** `fc7cc91d2eace8da2371371c2855c24cbcb326a1`  
**Prior Stable:** GLAZE UI V1.2 / `1.2.0`

## Release scope

V1.3.0 promotes the integrated Adaptive Resonance implementation as the current official consumer-eligible GLAZE UI design-system release.

The release includes the V1.3 token families and runtime modules for adaptive color, layout, Living Material 2.0, motion, shape, typography, accessibility/resilience, adaptive navigation, multi-pane composition, System Shell evolution, contextual intelligence, personalization, reachability and signature component experience.

Stable authorities:

- `VERSION` → `1.3.0`
- `registry/lifecycle.json` → current Stable/current official `1.3.0`
- `GLAZE_UI_V1_3.md`
- `tokens/glaze-v1.3.json`
- `js/glaze-v1.3.0.mjs`
- `acceptance/v1.3-stable.md`

The validated V1.2 web material/base layer remains inherited through `css/glaze-v1.2.0.css`; no synthetic V1.3 CSS aggregate is introduced.

## Bounded promotion decision

The project owner directed that V1.3 become Stable and that remaining Stable blockers/qualification obligations move to V1.3.1.

This release therefore does **not** claim that missing pre-promotion qualification evidence passed. Historical Candidate/readiness records remain truthful, including their blocked/pending results. The unresolved work is explicitly tracked in `acceptance/v1.3.1-hardening.md`.

## V1.3.1 hardening scope

- fresh human optical/icon-artwork collision review where required;
- manual assistive-technology qualification;
- physical/native/OEM/compositor/foldable/posture qualification;
- production performance/resource evidence;
- native Personalization persistence/system/wallpaper adapter qualification; and
- Stable source-namespace, compatibility, import/equivalence and rollback cleanup.

## Consumer migration

V1.3.0 is consumer-eligible, but every GoreeCloud consumer is independently migration-gated. `consumers/registry.json` now requires `1.3.0` while carrying no consumer forward as accepted by implication. Prior V1.2 evidence remains historical/migration input only.

Use `MIGRATION_V1_2_TO_V1_3.md` and the exact-revision adoption record schema in `contracts/v1.3/consumer-adoption-record.schema.json` for downstream migration.

## Non-claims

This source release does not by itself establish downstream production eligibility, physical-device certification, native parity, assistive-technology certification, distribution/signing acceptance, deployment, tag publication, or GitHub Release publication. Those remain separately traceable actions or evidence boundaries.
