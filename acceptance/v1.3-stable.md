# GLAZE UI V1.3 — Stable Source Acceptance

**Version:** `1.3.0`  
**Product:** GLAZE UI V1.3 — Adaptive Resonance  
**Lifecycle:** Stable  
**Promotion date:** 2026-09-07  
**Prior known-good Stable:** GLAZE UI V1.2 / `1.2.0`

## Project-owner lifecycle decision

On 2026-09-07 the GoreeCloud project owner directed that GLAZE UI V1.3 become Stable and that remaining Stable blockers/qualification obligations move to GLAZE UI V1.3.1. This record implements that bounded lifecycle decision.

This decision does **not** convert missing, pending, manual, physical-device, native-platform, OEM/compositor, foldable/posture, production-performance, Personalization-adapter, or source-namespace qualification into passing V1.3 evidence. The unresolved qualification work is preserved in `acceptance/v1.3.1-hardening.md`.

## Source and evidence boundary

- Integrated V1.3 implementation anchor before release promotion: `fc7cc91d2eace8da2371371c2855c24cbcb326a1`.
- The historical V1.3 qualification control plane and its evidence directory remain truthful historical records. At promotion, `evidence/v1.3/` does not establish completion of the previously defined all-lanes Stable qualification matrix.
- V1.3 Stable is therefore an explicit owner-approved bounded design-system release scope, not a claim that every earlier pre-promotion qualification gate completed.
- No historical acceptance or readiness record is rewritten from blocked/pending to passed by this promotion.

## Stable authority

- `VERSION` is `1.3.0`.
- `registry/lifecycle.json.currentStable` and `currentOfficial` are `1.3.0`.
- `GLAZE_UI_V1_3.md` is the Stable product contract.
- `tokens/glaze-v1.3.json` is the Stable V1.3 token-family manifest; underlying source artifacts retain their historical `.candidate` filenames.
- `js/glaze-v1.3.0.mjs` is the Stable runtime entrypoint over the integrated V1.3 implementation modules.
- The V1.2 Stable CSS entrypoint remains the inherited web material/base layer because V1.3 was implemented as token, runtime, contract, and reference extensions rather than a monolithic V1.3 CSS aggregate. This promotion does not invent an unvalidated CSS source layer.
- `consumers/registry.json` requires fresh V1.3 adoption without auto-accepting any consumer.
- V1.2 remains preserved as the prior known-good Stable rollback anchor.

## Deferred to V1.3.1

The following work remains qualification/hardening scope rather than accepted V1.3 evidence:

1. project-owner/human optical and icon/artwork collision review where fresh exact-revision review is required;
2. manual assistive-technology sessions;
3. physical-device/native-platform/OEM/compositor/foldable/posture qualification;
4. production performance/resource qualification, including representative frame pacing, latency, memory, GPU/compositor, power and thermal behavior where applicable;
5. native Personalization persistence, system appearance, and wallpaper-source adapter qualification; and
6. Stable activation/source-namespace cleanup, compatibility/equivalence verification, and removal of obsolete Candidate-only assumptions where safe.

These obligations are governed by `acceptance/v1.3.1-hardening.md` and must not be backfilled as V1.3 passes without evidence.

## Consumer boundary

V1.3 Stable makes the design-system release eligible for independent consumer migration. It does not establish downstream application conformance, production acceptance, native parity, physical-device acceptance, assistive-technology certification, distribution/signing acceptance, or deployment. Each consumer must create repository-local evidence against an exact consumer revision and the exact Glaze UI Stable revision it adopts.
