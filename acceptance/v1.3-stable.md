## Decision

GLAZE UI V1.3 — Adaptive Resonance is accepted as the current Stable GoreeCloud design-system release at version `1.3.0`.

This promotion is an explicit release-scope decision. It does **not** manufacture missing qualification evidence, relabel V1.2 evidence as V1.3 evidence, or claim that every earlier proposed V1.3 qualification workstream produced an accepted schema-v2 record.

## Accepted V1.3 release basis

The Stable decision is based on the following retained facts:

- the V1.3 implementation workstreams were implemented and repository-validated on the V1.3 development line;
- exact-source automated validation for `72ad63bf32d80420b25dc98bfd2def47bcc2a427` completed successfully, including Phase 0, Migration and Consumer Boundary, qualification control-plane, Stable-readiness control-plane, signature/reference validation, V1.2 Stable preservation, and zero-drift visual regression support;
- Human Optical + icon/artwork collision qualification was accepted for the exact qualified implementation anchor, including all 55 governed visual-quality rules and the required final visual-quality gates;
- Manual Assistive Technology qualification has a retained accepted V1.3 schema-v2 evidence record on the governed V1.3 evidence lineage;
- the project owner explicitly approved the remaining observed work as passing and then directed that any **remaining Stable blockers** be moved to V1.3.1 rather than block V1.3.0 Stable.

## V1.3.1 hardening handoff

The following work is **not represented as an accepted V1.3 schema-v2 qualification pass**. It is removed from the V1.3.0 Stable blocking set and becomes mandatory V1.3.1 hardening work:

1. `physical-device-native-platform-qualification` — retained representative physical-device/native-platform evidence and disposition;
2. `physical-device-production-performance-qualification` — retained representative production-performance/resource measurements and accepted budget disposition;
3. `native-personalization-adapter-qualification` — retained native persistence/system-appearance/wallpaper/fallback evidence for every claimed adapter/platform;
4. `stable-activation-and-source-namespace-cleanup` — source-namespace cleanup, equivalence/import-closure verification, and rollback hardening.

The authoritative handoff is `contracts/v1.3.1/hardening.plan.json`. These items must not be described as passed V1.3 evidence merely because V1.3.0 is Stable.

## Source and namespace policy

The qualified V1.3 implementation intentionally retains `*.candidate.*` source artifact names where those exact source files were the implemented and validated inputs. Stable entrypoints `css/glaze-v1.3.0.css` and `js/glaze-v1.3.0.mjs` provide the official release surface without rewriting qualified implementation history. Namespace cleanup and equivalence hardening is a V1.3.1 task.

## Consumer boundary

V1.3.0 is consumer-eligible as a design-system release. **No downstream GoreeCloud application or service becomes V1.3-conformant automatically.** The current consumer registry target advances to `1.3.0`; each consumer must provide fresh repository-local exact-revision V1.3 adoption and acceptance evidence before it can be recorded as accepted for the current Stable contract.

Historical V1.2 consumer acceptance remains valid history but does not automatically count as V1.3 acceptance.

## Rollback

GLAZE UI V1.2 / `1.2.0` remains retained as the prior known-good Stable rollback baseline. This Stable promotion does not rewrite or delete V1.2 acceptance history.
