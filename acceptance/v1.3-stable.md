# GLAZE UI V1.3 — Stable Release Authority

**Status:** Official Stable release  
**Version:** `1.3.0`  
**Product:** GLAZE UI V1.3 — Adaptive Resonance  
**Branch authority:** `main`  
**Consumer eligible:** Yes  
**Effective:** 2026-09-08  
**Owner directive:** Mandatory release-authority decision

GLAZE UI V1.3 / `1.3.0` is the current official Stable GoreeCloud design-system release and is eligible for consumer adoption from `main` through the Stable entrypoints `css/glaze-v1.3.0.css` and `js/glaze-v1.3.0.mjs`.

This is a lifecycle and consumer-eligibility decision backed by the V1.3 Adaptive Resonance implementation already integrated on `main`. It is not a claim that unfinished manual, human, physical-device, production-performance, or native-platform evidence has been manufactured or retroactively passed.

## Owner release decision

The project owner directs that issues which previously prevented V1.3 from becoming Official/Stable are no longer V1.3.0 release blockers. They are transferred to the V1.3.1 hardening and qualification track. V1.3.0 remains the authoritative Stable baseline while that follow-up work proceeds.

## V1.3.1 deferred obligations

The following unresolved work is preserved as V1.3.1 scope and remains unclaimed as completed evidence:

1. Human optical, visual-finish, and icon/artwork collision qualification, including the V1.3 quality-rule review set.
2. Manual assistive-technology qualification for the support matrix actually claimed.
3. Physical-device/native-platform qualification for claimed Android/OEM, Linux compositor/window, foldable/posture, and other native behavior.
4. Physical-device production-performance qualification, including accepted budgets and representative real-device measurements.
5. Native Personalization adapter qualification, including persistence, system-appearance, wallpaper-source, and fallback behavior where claimed.
6. Stable activation/source-namespace cleanup, migration/equivalence/import-closure/rollback hardening, now treated as V1.3.1 cleanup rather than a V1.3.0 lifecycle blocker.

These items must not be represented as passed until real evidence exists. Their transfer to V1.3.1 does not reduce consumer-local acceptance requirements.

## Consumer boundary

Consumer eligibility means GoreeCloud products may target V1.3.0 as the current official shared design-system release. It does not automatically make any downstream product conformant or production-ready. Each consumer remains responsible for repository-local implementation, accessibility, platform, workflow, performance, rollback, and production acceptance appropriate to that product.

## Stable source boundary

- Machine version authority: `VERSION` = `1.3.0`.
- Lifecycle authority: `registry/lifecycle.json` identifies `1.3.0` as current Official and current Stable.
- Required shared consumer target: `consumers/registry.json.requiredConsumerVersion` = `1.3.0`.

## Evidence integrity

Historical V1.3 Candidate/deferred qualification records remain useful provenance. Where those records previously described their workstreams as lifecycle blockers, the owner directive supersedes that blocking interpretation for V1.3.0. The underlying unresolved evidence state is preserved and transferred to V1.3.1; it is not rewritten as a pass.
