# GLAZE UI V1.1.1 — Stable Maintenance Acceptance

## Decision

GLAZE UI V1.1.1 is the governed maintenance release for the V1.1 Stable line. It corrects the CSS import-closure defect discovered after V1.1.0 without changing the approved V1.1 visual design, optical tokens, semantic authority, accessibility contract, component catalog, System Shell contract, or runtime behavior.

## Qualification evidence

The corrective source was first isolated as `1.1.1-rc.1`. After governed merge, exact `main` revision `1af31aa69a40e740cfcaaca7fd5eee340da98c22` completed the independent `Glaze V1.1 Post-Merge Release Evidence` workflow, run `34034770603`, successfully.

That exact-main gate included current Stable/import-closure validation, V1.1 specification and implementation validation, material/semantic/layout validation, source-pinned rendered web visual regression, and fresh framework-native Android handheld emulator acceptance.

The maintenance release therefore preserves the human-approved V1.1 visual baseline while correcting delivery/import closure.

## Stable package boundary

- Stable package version: `1.1.1`
- Web entrypoint: `css/glaze-v1.1.1.css`
- Runtime entrypoint: `js/glaze-v1.1.1.mjs`
- Patch contract: `contracts/v1.1/patch-1.1.1.json`
- Previous Stable: `1.1.0`
- Next-version Candidate: `1.2.0-candidate`

V1.1.0 remains immutable historical release evidence. V1.1.1 does not rewrite the old tag or GitHub Release.

## Consumer boundary

Promotion of the shared design-system package does not auto-migrate any GoreeCloud consumer and does not grant any downstream application production eligibility. Consumers must explicitly target `1.1.1` and pass their own current-revision conformance, accessibility, platform integration, and production-acceptance gates.

## Native evidence boundary

The Android evidence is bounded to the framework-native handheld reference used by the release-evidence workflow. It does not establish OEM-wide qualification, physical-device qualification, TalkBack certification, signing/distribution acceptance, or downstream application acceptance.

## Finalization rule

The immutable `v1.1.1` tag and GitHub Release may be created only from the exact merged Stable promotion revision after its post-merge source, rendered-web, and Android release-evidence gates pass. Canonical GoreeCloud project and changelog documentation must then be synchronized to the immutable release identity.
