## Exact-revision rule

All accepted blocking records must target the same exact 40-character source revision. Evidence for an earlier revision becomes historical input when source changes invalidate the observation. It may not be silently carried forward or relabeled.

## Evidence disposition rule

A qualification record contributes to readiness only when:

- `status` is `passed`;
- `disposition.accepted_for_lifecycle_gate` is `true`;
- target product/version are `GLAZE UI V1.3` / `1.3.0-candidate`;
- source revision matches the exact promotion candidate revision;
- required evidence references are independently inspectable;
- review authority mode is appropriate to the workstream;
- the record is not expired;
- no unresolved issue remains.

## Automated evidence boundary

The following may be established by repository CI:

- the qualification contract is coherent;
- evidence records conform to the required structure and core semantics;
- all accepted records, when present, target one exact source revision;
- implementation workstreams and migration controls remain validated;
- V1.2 Stable authority remains intact;
- Candidate entrypoints/lifecycle changes have not occurred prematurely;
- the readiness evaluator reports blockers deterministically.

The following are **not** established by repository CI alone:

- human optical quality;
- real assistive-technology usability;
- physical-device/native-platform behavior;
- physical-device production performance;
- native Personalization adapter acceptance;
- human acceptance of namespace/equivalence cleanup;
- formal lifecycle promotion.
