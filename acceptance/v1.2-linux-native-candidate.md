# GLAZE UI V1.2 — Linux GTK4 Native Candidate Evidence

## Purpose

This track proves bounded framework-native Linux desktop references for the GLAZE UI V1.2 Frosted Neutral Candidate, bounded compact/expanded window recomposition, and the Personalization / Living Frosted adapter boundary. It exercises the System Shell direction that replaces the earlier teal/blue-green substrate with neutral frosted white/gray or smoky graphite material while preserving GLAZE UI V1.1 / 1.1.0 as current Stable authority.

Passing this track does not establish Release Candidate, Stable, production, compositor, physical-display, physical-foldable, assistive-technology, native-form-factor-parity, or downstream-consumer acceptance.

## Native material contract

The GTK4 reference follows the V1.2 rule: **neutral glass first, color second**.

- Base, Raised, Overlay, Panel, and Critical System substrate roles use equal-channel neutral RGB values.
- Light surfaces are milky white / neutral gray translucent material.
- Dark and Deep Dark surfaces are smoky neutral graphite rather than blue-green glass.
- GoreeCloud blue and semantic colors are reserved for active controls, focus, selection, status, progress, and identity.
- The Quick Settings / Control Center panel remains neutral even when several controls are active.
- Reduced Transparency resolves translucent layers to opaque neutral surfaces.
- Critical System remains high-opacity and non-backdrop-dependent.

## System Shell reference coverage

The native GTK4 Frosted Neutral scene includes:

- a floating shell/navigation bar;
- Frosted Neutral hero/material reference;
- Universal Search using a Glaze entry layer;
- Quick Settings / Control Center with volume, brightness, Wi-Fi, Bluetooth, Night Light, Performance, Airplane Mode, and Focus examples;
- accent-only active setting states;
- Critical System high-opacity content;
- primary and secondary native actions;
- Light, Dark, and Deep Dark appearances;
- Reduced Transparency;
- Touch Assistance;
- 200% large-text layout;
- keyboard-focusable native controls.

A separate `window_adaptation.py` GTK4 reference covers bounded native desktop recomposition:

- runtime window width is treated as a fixture/capability input rather than device identity;
- a compact window remains a complete one-panel environment for the primary task;
- an expanded window keeps the same primary task and adds contextual detail instead of merely scaling the compact layout;
- the primary task value remains present across the compact and expanded evidence cases;
- the reference does not read hinge sensors, infer fold posture, select a production capability class, or claim physical foldable support;
- native form-factor parity remains an explicit open boundary.

A separate `personalization.py` GTK4 reference covers the V1.2 Extended Upgrade adapter boundary:

- Follow System reads the local `org.gnome.desktop.interface/color-scheme` setting when available.
- If that GNOME schema/key is unavailable, the adapter falls back to GTK's local `gtk-application-prefer-dark-theme` setting.
- Manual Light, Dark, and Deep Dark preferences override Follow System.
- Living Frosted Clarity normalizes to Clear, Balanced, or Dense; invalid values fail closed to Balanced.
- Wallpaper-derived atmosphere accepts only caller-supplied local RGB summary channels.
- The adapter performs no wallpaper image acquisition, decoding, remote fetch, telemetry, persistence, or cross-device synchronization.
- Wallpaper atmosphere is desaturated and bounded to maximum alpha 0.12 and maximum chroma retention 0.28.
- The bounded atmosphere is composited over a retained equal-channel neutral surface instead of replacing neutral material authority.
- Reduced Transparency suppresses decorative wallpaper atmosphere.
- Default action targets remain at least 48 px and Touch Assistance raises the floor to at least 56 px.

## Blur/compositor boundary

GTK4 can express translucent native surfaces, hierarchy, geometry, state, and native control behavior, but this headless reference does **not** claim compositor-wide backdrop blur fidelity. Real wallpaper/background diffusion in the GoreeCloud desktop shell requires integration with the production Wayland compositor / shell blur mechanism and must be validated separately on supported hardware and compositor configurations.

The absence of that later compositor gate does not permit replacing the neutral Frosted Neutral substrate with a teal or blue-green fill.
